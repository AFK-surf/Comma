# R8 与产物隔离

Release、internal、benchmark 共用 AGP 的 `optimization.enable = true`，使用 R8 full mode，开启代码删除、优化、混淆和资源压缩。Debug 不压缩。Internal 和 benchmark 从 release 继承优化配置。

## 动态入口

应用没有按字段名反射的序列化和实体映射。JSON 和 SQLite 都显式读写键和列名。库和 AndroidX 使用自带的 consumer rules，应用不添加整包 keep。`:scroll` 的 consumer rule 保护 XML `layoutManager` 通过类名加载的构造器。

每条自定义 keep rule 都要说明所保护的入口。不要为隔离检查保留业务类的名称，也不要阻止业务代码优化。

## 检查与符号文件

`verify-release-isolation.py` 要求每个非 debug 产物都有对应变体的 `mapping.txt`，并检查 R8 mapping 和 full mode。它确认 APK 不含夹具、演示页、测量工具、ASR 字段和凭据字节。

```sh
python3 -m unittest discover -s scripts -p 'test_*.py'
```

内部构建把 mapping 保存为 `dist/comma-staging-<versionName>-mapping.txt`。必须和同版本 APK 一起保留。用 R8 Retrace 或 Android Studio 分析同事反馈的堆栈。不要使用其他版本的 mapping。

共享机器可以用 `COMMA_GRADLE_COMMAND` 指定 Gradle 启动命令和固定参数。默认为 `./gradlew --max-workers=2`。
