# Client unit test files whose two runs of the determinism proof
# (scripts/determinism/run-unit.sh: base, and all perturbations at once) did
# not record the same execution. They run in the deterministic unit suite and
# stay outside determinism/manifest.txt's @unit entry until the harness gives
# them one execution; they are fixed in batches by common cause in the
# harness. A file leaves this list once proven. It grows only on a pull
# request labeled determinism-list-grow.
#
# OnboardingOverlay: "plays once as the screen starts to dim" checks a
#   different number of times from run to run.
# AiInput: the first tooltip hovered in a test opens only after a pointer
#   move in an earlier test (React Aria keeps the input modality for the
#   document), so a shuffled order fails it.
# Login, ConversationView: the same input modality decides whether a focused
#   control shows data-focus-visible.
# compute-node-recovery, ipc-gateway, driveStore, evidence-store,
#   conversationChannel, ended-test-timers: node tests read the machine's
#   clock (Date): the node project has no test clock yet.
# textReveal, ConversationThread.multimodal, Plugins: names from the
#   application's own module counters (comma-text-reveal-N, plugin-flight-N)
#   count what earlier tests of the file made.
# RecommendationRail: a link an earlier test hovered is previewed when it
#   renders, not when it is hovered, so the preview's time differs.
# onboarding-window: Vitest's mock invocationCallOrder counts the calls of
#   earlier tests.
# airdrop-vfs-source: memfs inode numbers count the files earlier tests made.
# audio-capture: records the worker's process id.
# iroh: its endpoint key comes from native code's own entropy.
# native-bridge index: zod's lazy `shape` getter becomes a value once an
#   earlier test reads it.
# golden: its only test is a placeholder that runs nothing (no golden runs
#   are kept).
# stories: some stories' tests make no observation.
