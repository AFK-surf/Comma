# 细粒度布局后的搜索范围

2026-09-06。建议将优化后的单频道查询先按 **60 天常用、90 天扩展**规划；不要据此统一开放半年或全年。

这是一项本地读取预算模拟，不是已经上线的搜索能力。输入来自 staging 当天 16:07:47–16:07:48（Asia/Shanghai）的按天、按频道统计；日内时间、版本、正文、文件清单和向量值均为合成内容。

后续决定：用户选择 2,048 粒度，线上迁移尚未实施。本实验同时调整 `slack_messages`、`slack_message_payloads`、`slack_semantic_documents` 和 `slack_semantic_files` 四张表；如果只改派生索引表，不能沿用这里的通过范围。普通消息读写与共享资源的[影响范围已单列](../../../../docs/salix/slack-semantic-read-layout.md#2048-粒度决定与影响范围)。选择该参数不等于已选择或上线 60/90 天的产品窗口。

## 窗口结果

对 37 个已有语义索引的频道分别重放相同 SQL。保留 65,536 行、256 MiB 读取量、128 MiB 查询内存、1 线程、2 秒预算，每次最多 20 个候选；256 MiB 是前述补丁预算。每条件单次、顺序执行，没有把延迟作为生产 P95。

| 时间跨度 | 2,048 粒度：预算通过频道数 | 1,024 粒度：预算通过频道数 |
| --- | ---: | ---: |
| 30 天 | 37 / 37 | 37 / 37 |
| 60 天 | 37 / 37 | 37 / 37 |
| 90 天 | 37 / 37 | 37 / 37 |
| 180 天 | 34 / 37 | 36 / 37 |
| 365 天，覆盖当前约 328 天历史 | 30 / 37 | 35 / 37 |

失败均为读取行数超限。1,024 的全年失败点是历史消息最多的两个频道，分别约 26,853 和 21,222 条消息。缩小粒度减少了多读的行，但无法取消多表扫描本身的成本。

| 范围 | 2,048 最大读取行数 | 1,024 最大读取行数 |
| --- | ---: | ---: |
| 30 天 | 36,100 | 31,087 |
| 60 天 | 53,315 | 44,666 |
| 90 天 | 63,218 | 52,545 |

90 天时，2,048 已使用约 96.5% 的行数预算，1,024 约 80.2%。因此，如果产品需要稳定覆盖 90 天，1,024 更值得作为候选；以 60 天为主要目标时，2,048 保留了约 18.6% 的行数余量，可以优先比较其较低的维护开销。这些是规划建议，仍需真实新表验证。

## 数据与模拟边界

统计输入包括 118,729 条源记录（含删除记录）、118,724 条 payload 记录、65,447 条文本索引记录和 2,404 条文件索引记录。已索引单元为文本 80,741 加附件 21,905，共 102,646。后台索引在继续推进，不能与当天较早的 91,541 单元快照混为同一时刻。

模型保留每个租户/工作区/频道/日期的记录数，以及该日每种向量数量对应的索引记录数。它在日内均匀分配合成消息时间，生成合成正文和文件关系，并重新构建 Compact parts。分区/part 布局、真实正文大小、版本历史、文件复用关系和真实向量质量都没有完整复制，不能将收益全部归因于粒度，更不能据此承诺实际线上延迟。

完整单键导出曾因传输超时中止，最终使用的是全部成功返回的每日聚合数据，不使用半份导出拼接结果。查询均只读；三份临时元数据文件已从 pod 删除，本地专用容器已停止。

**索引覆盖尚未完成。** 当前文本索引记录少于源记录，部分附件也未完成处理。索引补齐和数据增长后，读取范围必须重新验收。预算通过只表示这份模型的 SQL 没有触发限制，不表示所有消息均已索引或每次必能找齐结果。

本轮仍是单频道读取；它没有实现 group 的所有 connect 跨频道搜索。跨频道、全历史的正式能力仍需[独立检索入口和发布协议](../../../../docs/salix/message-search-target.md)落地，并使用真实向量及完整授权/发布链路验证。

```sh
  --metadata devtools/search-capacity/results/2026-09-06/daily-shape-inputs \
  --query devtools/search-capacity/results/2026-09-06/row-read-baseline.sql \
  --granularity 2048 --output /tmp/window-2048.json
```
