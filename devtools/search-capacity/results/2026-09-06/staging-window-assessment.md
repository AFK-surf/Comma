# staging 搜索时间范围评估

2026-09-06，Asia/Shanghai 14:41–14:55 的只读统计与 SQL 重放。

**建议现有查询路径默认 14 天、允许扩大到最多 30 天；以 256 MiB 读取预算补丁生效为前提。暂不直接放到 60/90 天。**

已部署模块仍采用 64 MiB 默认读取预算，交互读取没有 256 MiB 覆盖；线上 API 仍限制单频道、最多 14 天。下面的 30 天结果来自使用补丁预算的 SQL 重放，不能当作当前 API 已支持 30 天。

独立索引方案可继续以全历史为目标。当前总量没有显示必须按 14/30 天截断的容量压力，但仍需补齐索引、用真实 WeMM 向量检验召回与延迟。不能把合成语料的百万单元边界直接当作现有 SQL 或真实向量的保证。

最早消息日期为 2025-10-13，现有历史约 328 天。上表为整个 staging 的跨租户总量，同一 Slack 来源在不同租户下的隔离副本分别计数；不是某个 group 的授权范围。它可作为当前单个 group 数据规模的保守参照，不能替代 group/connect 授权解析。

现有文本索引有 58,273 条消息记录、71,585 个单元；附件索引有 2,059 条记录、19,956 个单元。文本索引记录少于消息总量，另一租户的镜像尚无对应语义索引；部分消息/附件可能没有可索引内容，或尚未处理。因此，91,541 不能代表完整历史索引补齐后的最终规模，也不是所有单元都已通过最新源状态校验的数量。

已索引附件单元包含文档文本 12,281、OCR 3,427、转写 2,454、图片 1,518、视频片段 276。消息镜像标记的文件引用共 7,257 个；引用数不等于唯一文件数，也不能直接作为待处理文件数。

## 现有 SQL 的窗口边界

在 staging ClickHouse 26.4.1.2212 上，重放工作区现有 SQL，使用已提出的 256 MiB 交互读取预算，其余预算保持为 65,536 读取行、128 MiB 查询内存、1 线程、2 秒执行时间。使用合法的合成查询向量，每次最多取 20 个候选；没有调用 GPU、Slack 权限接口或最终 PG 状态检查。

这是绕过 API 的 14 天参数限制进行的只读评估。每个条件是单次、顺序 SQL 测量；缓存没有清空，不报告为生产 P95、并发 SLA 或完整入口延迟。

| 代表频道特征 | 最大已通过窗口 | 第一个失败窗口 | 失败原因 |
| --- | ---: | ---: | --- |
| 近期最繁忙 | 30 天 | 60 天 | 读取约 71,090 行，超过 65,536 |
| 原默认窗口故障频道 | 30 天 | 60 天 | 读取约 65,860 行，超过 65,536 |
| 全历史消息最多 | 90 天 | 180 天 | 读取约 68,590 行，超过 65,536 |
| 附件单元较多 | 60 天 | 90 天 | 读取约 65,670 行，超过 65,536 |

首次失败后停止扩大该频道的窗口，未测更大窗口不记为通过。

随后对全部 **37 个已有语义索引的租户/工作区/频道组合**重放 30 天查询，37/37 成功。单次请求耗时最大 371 ms，数据库读取最大 59,440 行、145,069,423 B（约 138.3 MiB），峰值查询内存最大 60,822,453 B（约 58.0 MiB）。代表频道首轮 30 天重放的最大耗时为 406 ms。

30 天点的最大读取行数已经达到预算的约 91%，后续消息增长、版本及 part 布局变化仍可能触发预算。默认保持 14 天是留出余量的操作建议；30 天适合作为可选最大跨度，不能承诺每次都成功。超预算继续返回缩小范围的现有可操作错误。

限制来自当前多表读取、版本归并、原文状态校验和 granule 读取成本。虽然 60 天只有约 4.36 万个已索引单元，某些单频道查询已经累计读取超过 6.55 万行；两种计数不能混用。

## 实施含义

- 当前入口：先使已有 256 MiB 修复生效，再考虑将参数允许跨度从 14 天扩大到 30 天；保留默认 14 天与现有其他预算。本次没有修改 API 或部署。
- 新独立索引：继续验证全历史，当前约 11.87 万条消息、9.15 万已索引单元是容量评估起点。补齐后的总量、真实向量分布、完整发布/授权路径与并发验收仍需完成。
- 不根据简单的“每天消息数 × 天数”承诺容量，也不自动提高读取行数预算来掩盖当前布局问题。

原始数值、预算代码观察、失败响应与逐请求统计见 [staging-window-data.json](staging-window-data.json)。容量原型的配置与限制见 [主压测报告](report.md)。统计分多次有界读取完成，不是跨表一致快照；查询日志的首次 24 小时盘点触发了 100 万行只读预算，其失败也保留在原始记录中，未据此编造数据。
