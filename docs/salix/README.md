## Living Incremental Session Handoff

Internal Sessions optionally maintain a disposable, advisory handoff projection in PostgreSQL (`salix_session_handoffs`, bound to `salix_sessions` with `ON DELETE CASCADE`) so automatic compaction can cut over inline without a foreground summarization LLM call.

- **Pre-cutover invariance:** Ordinary model requests are byte-identical whether living handoff is enabled or disabled.
- **Background updater (`SalixAgent.LivingHandoff`):** Runs after settled rounds (including `:async_tools_started`) on a dedicated `:handoff` `DependencyRunner` / `DependencyAdmission` bucket with independent global and per-tenant caps. Gates on an explicit positive context window (`context_tokens`), summary compaction strategy, and `ratio >= start_ratio`. Never hydrates from S3 or holds the Session handle.
- **Certified watermark chain and CAS:** `CompactionHost.handoffWindow` selects tool-closed groups behind the protected hot tail and certifies both `covered_from` (`covered_prefix_digest`) and `through` (`prefix_digest`) via canonical ETF hashing. `SalixStore.SessionHandoffs.apply_update/3` serializes against `salix_sessions` (`FOR NO KEY UPDATE`), checks `revision` plus `expected_basis`, enforces 4 KiB soft / 8 KiB hard / 2 KiB per-statement limits, and redacts credentials (known vendor token prefixes and named credential assignments with single-, double-, or backtick-quoted values or unquoted values of at least 8 characters, including JSON keys and uppercase literals; explicit `$ENV` / `${ENV}` references and paths are preserved). Same-generation digest mismatch atomically invalidates the stale row via `delete_if_revision/4` and resets the bounded supervised ETS watermark hint so the next round bootstraps cleanly. After an inline cutover, the updater performs a zero-LLM lazy rebase onto `(S+1, H)`.
- **Zero-stall cutover (`CompactionHost.prepare` / `CompactionHost.commit`):** Automatic `:maybe_compact` cuts over inline when a valid handoff matches `(summary_sequence, compacted_through, prefix_digest)`, lands on a tool-closed boundary, and leaves full surviving tail bytes (including unfinished activation input) within `15%` of window bytes (`0.15 * window_tokens * 4`, or `16 KiB` during `overflow_recovery`). Eligible inline cutover bypasses `compaction_recovery_active` and `compaction_backoff`, and `Compaction.perform/3` answers inline once the plan carries `handoff`. `CompactionHost.commit` rechecks both tool closure and the surviving tail cap against `fencedLive` and rejects with `{:error, {:stale_compaction_snapshot, ...}}` if an interleaved append invalidates either. Explicit `:compact`, `provider_compaction`, custom `:summarizer`, or any stale/missing handoff falls back to normal synchronous compaction.
