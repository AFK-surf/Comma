\section{产品概览}

Bridge For Teams 是面向团队的智能协作工作台。团队可以在同一个 Dashboard 中管理组织、Agent Swarm、成员、Agent、任务、集成、设备和网站。

本手册面向普通成员、Agent Swarm 管理员和组织管理员，说明日常使用中会看到的页面与操作。不同角色可见的菜单和按钮可能不同；如果缺少某个入口，请先向组织 owner 或 admin 确认权限。

\section{核心概念}

\begin{longtable}{p{3.2cm}p{10.6cm}}
\toprule
概念 & 说明 \\
\midrule
组织 & 团队或公司的协作空间。成员、组织设置和 Agent Swarm 都归属于组织。 \\
Agent Swarm & 围绕一个业务目标建立的工作空间，用来组织 Agent、任务、集成、设备和网站。 \\
成员 & 被授权访问组织的用户。组织角色包括 owner、admin 和 member。 \\
Agent & Agent Swarm 中负责接收请求并分配工作的智能助手（Router Agent）。任务在 Agent Swarm 的默认运行位置和默认任务模型上运行。 \\
任务 & 团队交给 Agent 处理的工作。任务详情页保留后续消息和执行进展。 \\
计划 & 按预定时间触发的工作，在任务详情中添加和编辑，在 \textbf{Tasks} 的 \textbf{Scheduled} 视图中查看和删除。 \\
集成 & 把 Slack 或 Feishu 等消息入口连接到 Agent Swarm。 \\
连接 & Agent Swarm 使用的第三方帐号授权，与消息集成分开管理。 \\
Runner & 由组织管理、用于承载设备工作的机器。Runner 在 \textbf{Fin} 中添加和维护。 \\
设备 & Agent 可使用的远程工作环境。创建设备前，需要组织中有可用 Runner。 \\
网站 & Agent 发布并归属于当前 Agent Swarm 的网站，列在 Agent Swarm 的 \textbf{Overview} 中。 \\
\bottomrule
\end{longtable}

\section{登录、创建组织与退出}

\subsection{登录 Dashboard}

\begin{enumerate}
  \item 打开 \url{https://teams.bridge.surf}。
  \item 按登录页提示选择或填写组织。
  \item 如果组织启用了单点登录，请在组织的登录服务中完成身份验证。
  \item 验证成功后返回 Dashboard。
\end{enumerate}

如果页面提示组织不存在、登录方式未配置或帐号没有访问权，请联系组织 owner 或 admin 确认组织和成员设置。

\subsection{使用邀请码创建组织}

\begin{enumerate}
  \item 在登录页选择 \textbf{Create organization with invite code}。
  \item 填写 \textbf{Invite code}。
  \item 填写 \textbf{Organization name} 和 \textbf{Organization slug}。
  \item 填写创建者的 \textbf{Work email} 和 \textbf{Name}。
  \item 点击 \textbf{Create organization}。
\end{enumerate}

创建者会成为新组织的 owner。邀请码只能使用一次；如果提交失败，请确认邀请码仍然有效，并检查邮箱、组织名称和 slug。

\subsection{退出登录}

打开左侧边栏底部的用户菜单，选择 \textbf{Sign out}。

\section{Dashboard 导航}

Dashboard 的左侧边栏按使用范围分组：

\begin{itemize}
  \item 顶部的组织切换器：列出你所属的组织，用于切换当前组织。
  \item \textbf{Workspace}：包括 \textbf{Overview}、\textbf{Agent Swarms}、\textbf{Fin}，以及按角色显示的 \textbf{Health}。
  \item 当前 Agent Swarm：包括 \textbf{Overview}、\textbf{Tasks}、\textbf{Agents}、\textbf{Devices} 和 \textbf{Settings}。
  \item \textbf{Configure}：包括 \textbf{Plugins}、\textbf{Skills} 和 \textbf{Connections}。
  \item \textbf{Administration}：包括 \textbf{Members}、\textbf{Organization plugins} 和按角色显示的 \textbf{Settings}。
\end{itemize}

顶部面包屑显示当前位置。使用 \textbf{Search navigation} 或快捷键提示，可以快速查找页面。窄屏设备会把同一组导航放入抽屉菜单。

\section{组织概览}

\textbf{Overview} 展示当前组织的概况和可访问资源。若要切换到其他组织，使用左上角组织切换器；若要查看全部组织，选择 \textbf{View all organizations}。

普通 member 只会看到已获授权的 Agent Swarm。owner 和 admin 可以查看组织范围的管理入口。

\section{组织与成员管理}

\subsection{查看和切换组织}

\begin{enumerate}
  \item 打开左上角组织切换器。
  \item 直接选择另一个组织，或点击 \textbf{View all organizations}。
  \item 在组织列表中选择要进入的组织。
\end{enumerate}

\subsection{角色说明}

\begin{longtable}{p{3cm}p{10.8cm}}
\toprule
角色 & 典型权限 \\
\midrule
owner & 管理组织、成员、组织设置和所有 Agent Swarm。系统会保护组织的最后一个 owner。 \\
admin & 管理大多数组织资源和 Agent Swarm，适合团队管理员。 \\
member & 使用已获授权的 Agent Swarm 和任务，适合普通团队成员。 \\
\bottomrule
\end{longtable}

\subsection{添加成员}

\begin{enumerate}
  \item 在 \textbf{Administration} 中打开 \textbf{Members}。
  \item 点击 \textbf{Invite member}。
  \item 填写成员邮箱并选择角色。
  \item 点击 \textbf{Add member}。
\end{enumerate}

添加后，请通知成员使用对应组织完成登录。owner 或 admin 也可以在成员列表中调整角色或移除成员。系统不允许降级或移除最后一个 owner。

\section{组织设置}

有权限的用户可以从 \textbf{Administration} 打开 \textbf{Settings}。侧边栏中的 \textbf{Settings} 子菜单包含 \textbf{General}、\textbf{AI models}、\textbf{Single sign-on} 和 \textbf{Integrations} 四个页面。

\subsection{General}

\textbf{General} 用于维护组织名称、slug、图标和默认语言，并管理 BFT CLI 的登录会话。修改后点击 \textbf{Save}。

\subsection{AI models}

\textbf{AI models} 用于限制组织可使用的模型，并设置默认模型：\textbf{Default Router model} 是新 Router 使用的模型；\textbf{Default Task model} 是没有设置自己默认任务模型的 Agent Swarm 中任务使用的模型。调整前应确认现有 Agent 是否依赖即将停用的选项。

\subsection{Single sign-on}

\textbf{Single sign-on} 用于配置组织登录方式。保存后，应使用测试帐号在新的浏览器会话中验证登录，再通知全体成员切换。

每个组织只有一个登录连接，可以在 \textbf{Provider} 中选择通用 OIDC、Feishu 或 Lark。切换提供方会替换当前连接，并且需要重新填写新提供方的密钥。

\textbf{使用 Lark 登录}：

\begin{enumerate}
  \item 在 Lark 开发者后台创建自建应用，或选用已有的应用，在凭证页面找到 \textbf{App ID} 和 \textbf{App Secret}。
  \item 在 \textbf{Single sign-on} 的 \textbf{Provider} 中选择 \textbf{Lark}，填入 App ID 和 App Secret。App Secret 保存后不再显示；留空表示保留已保存的值。
  \item 复制页面显示的 \textbf{Redirect URI}，在 Lark 开发者后台打开应用的“安全设置”，把这个地址添加到重定向 URL。
  \item 登录本身不需要任何权限。如需记录成员的邮箱，请在 \textbf{Lark scopes} 中填写 \texttt{contact:user.email:readonly}，并在 Lark 开发者后台为应用开通这项权限。请在成员首次登录前确定权限范围。
  \item 点击 \textbf{Save}，再点击 \textbf{Run checks}。检查只确认 App ID、App Secret 已保存并给出要登记的地址，不会向 Lark 验证密钥。
  \item 在新的浏览器会话中打开组织的登录页，点击 \textbf{Sign in with Lark}，用测试帐号完成登录。
\end{enumerate}

这里保存的 App ID 和 App Secret 只用于登录，与 Agent Swarm 的 \textbf{Connections} 中连接的 Lark 机器人应用互不影响。Lark 帐号与 Feishu 帐号是不同的登录身份：组织从其他登录方式切换到 Lark 后，成员首次用 Lark 登录时会成为新成员，角色为 \textbf{Role on first sign-in} 中设置的角色，请在切换前安排好 owner 和 admin 的权限。

\subsection{Integrations}

\textbf{Integrations} 页面包含 \textbf{OAuth apps}、\textbf{Composio}、\textbf{Signal} 和 \textbf{Feishu} 四个部分。\textbf{OAuth apps} 用于管理组织授权的应用，\textbf{Composio} 用于配置可供 \textbf{Connections} 使用的服务。敏感凭据保存后不会再次完整显示；需要更换时，请使用页面提供的更新或撤销操作。

\subsection{Feishu}

Feishu 应用先在组织级完成登记，再由 Agent Swarm 选择使用。这样，同一份组织配置可以用于 Dashboard 登录或群机器人。

\begin{enumerate}
  \item 打开 \textbf{Settings} → \textbf{Integrations}，找到 \textbf{Feishu} 部分。
  \item 添加 Feishu app，并按页面提示填写显示名称、应用标识、应用密钥和机器人验证信息。
  \item 根据用途选择 \textbf{Use for dashboard sign-in}、\textbf{Use for the group bot}，或同时选择两项。
  \item 保存后，使用页面展示的地址和检查项完成 Feishu 管理后台配置。
\end{enumerate}

当前每个组织只能有一个启用群机器人用途的 Feishu app，并且该机器人同一时间只连接一个 Agent Swarm。变更连接前，请先确认现有群聊不会受影响。

\section{Fin：管理 Runner}

\textbf{Fin} 是组织的 Runner 管理入口。Runner 列表会显示状态、容量、主机信息、版本和最近在线时间。

\subsection{添加 Runner}

\begin{enumerate}
  \item 在 \textbf{Workspace} 中打开 \textbf{Fin}。
  \item 点击 \textbf{Add runner}。
  \item 按页面提示填写名称，并生成一次性安装命令。
  \item 复制命令，在目标 Mac 上执行。
  \item 返回 \textbf{Fin}，等待新 Runner 显示为可用。
\end{enumerate}

安装命令只在生成时展示，并且会在短时间后失效。不要把命令转发给无关人员；若未及时使用，请重新生成。

\subsection{维护 Runner}

展开 Runner 可查看更详细的状态和容量。owner 或 admin 可以使用页面提供的 \textbf{Rotate access}、\textbf{Revoke} 和 \textbf{Remove} 等操作。普通 member 可以查看 Runner，但不能执行管理操作。

设备创建页面若提示没有可用 Runner，请先点击 \textbf{Open Runners}，完成 Runner 添加或恢复后再重试。

\section{Agent Swarm 管理}

\subsection{查看和搜索 Agent Swarm}

在 \textbf{Workspace} 中打开 \textbf{Agent Swarms}。列表只显示当前用户有权访问的项目，可使用筛选框按名称、slug 或运行时 ID 查找。列表滚动到底部时会继续加载。

\subsection{创建 Agent Swarm}

\begin{enumerate}
  \item 点击 \textbf{New Agent Swarm}。
  \item 填写名称。slug 会按名称自动生成，可按需修改。
  \item 点击 \textbf{Create Agent Swarm}。字段有误时，错误会显示在对应字段下方。
  \item 创建后自动进入该 Agent Swarm，继续添加 Agent、成员和集成。
\end{enumerate}

名称用于界面展示；slug 用于稳定链接，建议使用简短、清晰的英文小写名称。

\subsection{访问权限}

打开 Agent Swarm 的 \textbf{Settings}，找到 \textbf{Access} 部分。Agent Swarm 管理员可以通过邮箱添加用户，调整角色（\textbf{Admin} 或 \textbf{User}），或移除访问权限。

组织 owner 和 admin 通常具有组织范围的管理权；普通 member 需要明确加入后才能看到对应 Agent Swarm。

\section{Agents}

\textbf{Agents} 列出当前 Agent Swarm 的 Router Agent。点击 Agent 名称，会在右侧打开详情，显示角色、状态、模型、运行时 ID 和系统提示词。详情页地址可以直接分享。

Agent Swarm 不再使用 Worker Agent：任务在 Agent Swarm 的默认运行位置和默认任务模型上运行，二者在 Agent Swarm 的 \textbf{Settings} 中设置。以前创建的 Worker Agent 保留为历史记录，只能查看；进行中的任务和定时计划会照常完成。

\subsection{配置 Router Agent}

Agent Swarm 管理员可以在 Router Agent 详情中点击 \textbf{Configure}，选择模型并编辑系统提示词。不选择模型时，Router 使用组织的默认 Router 模型。

Router Agent 的详情中还显示 Router 标准会话。管理员可以点击 \textbf{Start new session} 开始新会话；当前工作会停止，原会话的历史记录仍可查看。

\section{Tasks 与定时计划}

\subsection{创建和跟进任务}

\begin{enumerate}
  \item 在 Agent Swarm 中打开 \textbf{Tasks}。
  \item 点击 \textbf{New task}。
  \item 填写目标和必要背景。
  \item 在 \textbf{Run on} 中选择运行位置：Salix、Cloud VM（Agent Swarm 开启 Cloud VM 时）或一台已连接、可以运行任务的设备；在 \textbf{Model} 中选择模型。两项默认都是 Agent Swarm 的设置。Agent Swarm 的成员都可以创建任务。
  \item 提交后打开任务详情，查看进展。
  \item 需要补充信息时，在任务详情中继续发送消息。
\end{enumerate}

任务描述应包含清晰目标、可验证结果和必要限制。不要在任务中粘贴不应共享的敏感凭据。

\subsection{管理计划}

计划在任务详情中添加和编辑。在 \textbf{Tasks} 右上角的筛选中选择 \textbf{Scheduled}，可以查看当前 Agent Swarm 的全部定时计划，并删除不再需要的计划。创建或修改计划时，确认时区、触发时间、目标 Agent 和任务内容。

\section{Connections}

Agent Swarm 的 \textbf{Connections} 页面分为两部分：

\begin{itemize}
  \item \textbf{Messaging}：成员通过哪些消息渠道联系 Agent Swarm，以及 Agent Swarm 在哪里回复。目前支持 Feishu、Slack、QQ 和 Signal。
  \item \textbf{Accounts}：Agent 代表团队使用的第三方帐号，包括 OAuth 帐号和通过 Composio 连接的应用。
\end{itemize}

Agent Swarm 的所有成员都可以查看此页面。只有 Agent Swarm 管理员可以新增、启用、停用、删除或断开连接。

\subsection{连接 Feishu}

\begin{enumerate}
  \item 请组织 owner 或 admin 先在 \textbf{Settings} → \textbf{Integrations} 的 \textbf{Feishu} 部分完成组织级配置，并启用 \textbf{Use for the group bot}。
  \item 进入目标 Agent Swarm，打开 \textbf{Connections}，找到 \textbf{Feishu} 部分。
  \item 选择组织已登记的 Feishu app，填写 \textbf{Connect name}，点击 \textbf{Connect}。
  \item 按页面检查项，在 Feishu 管理后台完成权限、事件订阅和回调配置。
  \item 返回 Dashboard，点击 \textbf{Run checks}。
  \item 把机器人加入测试群并发送一条消息，确认任务或回复出现在预期的 Agent Swarm。
\end{enumerate}

如果页面提示没有可选的 Feishu app，请先返回组织设置完成登记。若 app 已连接其他 Agent Swarm，请确认影响后再调整。

\textbf{飞书云文档}：Agent 以机器人身份读取和编辑飞书文档，包括知识库中的新版文档。机器人只能打开三类文档：分享给机器人所在群的文档、添加了该应用的文档，以及在组织内开放链接访问的文档。需要 Agent 处理某篇文档时，在文档的“分享”中把机器人所在的群添加为协作者。较早配置的 app 需要重新导入页面上的权限 JSON，并发布新版本，才能使用文档功能。电子表格、多维表格和旧版文档暂不支持。飞书妙记按相同规则分享给机器人所在的群后，Agent 可以读取妙记的摘要、待办、章节、文字记录和音视频，但不能编辑妙记。

\subsection{连接 Slack}

\begin{enumerate}
  \item 进入 Agent Swarm 的 \textbf{Connections}，在 \textbf{Slack} 部分点击 \textbf{Add Slack app}。
  \item 按对话框提供的 manifest 在 Slack 中创建应用。
  \item 把页面要求的应用信息填回 Dashboard。在 \textbf{Deliver Slack messages to} 中选择 Router Agent（默认），或选择 \textbf{Tasks}：每个新的 Slack 话题会成为一个任务，并可为这些任务选择模型（不选时使用 Agent Swarm 的默认任务模型）。然后保存。
  \item 点击 \textbf{Open install URL}，在 Slack 中完成安装和授权。
  \item 把应用加入测试频道并发送消息，确认消息由预期 Agent Swarm 处理。
\end{enumerate}

应用权限或事件订阅发生变化后，请重新完成页面给出的检查。停用或删除 connect 前，先通知仍在使用对应群聊或频道的成员。

\subsection{连接 QQ}

QQ 通过 QQ 开放平台的机器人接入。每个机器人连接一个 Agent Swarm，成员可以在 QQ 群里 @机器人，也可以和机器人私聊。

\begin{enumerate}
  \item 在 QQ 开放平台创建机器人，在机器人的开发设置中找到 \textbf{AppID} 和 \textbf{AppSecret}。
  \item 进入 Agent Swarm 的 \textbf{Connections}，在 \textbf{QQ} 部分点击 \textbf{Add QQ bot}，填入 AppID 和 AppSecret 并点击 \textbf{Connect}。
  \item 复制页面显示的 \textbf{Callback address}。在 QQ 机器人管理端把事件接收方式选为 Webhook，保存这个回调地址，并订阅单聊事件、群聊事件、互动事件和群成员事件。
  \item 把机器人加入测试群并 @它 发送一条消息，或直接私聊机器人，确认消息由预期的 Agent Swarm 处理。
\end{enumerate}

使用时请注意 QQ 平台的几项规则：

\begin{itemize}
  \item \textbf{回复时限}：在群里，机器人只能在被 @ 后 5 分钟内回复，最多 5 条。任务耗时更长时，需要群管理员在该群的机器人设置中打开“机器人主动在群聊内发言”，机器人才能稍后把结果发回群里。私聊中，机器人可以在 60 分钟内回复，之后也可以主动发消息，除非对方关闭了机器人的主动消息。
  \item \textbf{消息不能修改}：QQ 不支持修改已发送的消息，机器人不会更新之前的消息，进展和结果都以新消息发出。
  \item \textbf{群聊消息记录}：机器人收到的群消息会被记录，供 Agent 查看和搜索此前的对话。群默认只把 @机器人 的消息发给它。需要记录完整对话时，群管理员在该群的机器人设置中把“机器人可获取的群聊消息范围”改为“获取群内全部消息”；选择“获取 @机器人的最近 10 条消息”时，机器人只在被 @ 时看到此前的 10 条消息，这些消息不会被记录。切换范围时，QQ 会在群里提示全体成员。私聊不会被记录。
  \item \textbf{指令菜单}：在输入框输入 \texttt{/} 会看到机器人的指令菜单。\texttt{/status}、\texttt{/compact} 和 \texttt{/help} 固定在菜单里，\texttt{/help} 会列出可用指令并介绍机器人能做的事。管理员可以在 \textbf{Connections} 的 QQ 机器人上点击 \textbf{Edit menu}，添加、修改或移除快捷项：每个快捷项有名称、说明、交给 Agent 的提示词、显示范围（私聊、群聊或两者），并可设为仅群管理员可点。保存后菜单立即生效。新连接的机器人默认带有群聊快捷项“总结群聊”。如果机器人在 QQ 机器人管理端已有自建的指令面板，QQ 会继续显示那个面板，需要先在管理端删除它。
  \item \textbf{文件}：机器人可以发送图片和文件，单个文件不超过 200 MB；成员发到群里或私聊中的文件，机器人可以读取。QQ 不向机器人开放“群文件”列表，机器人读不到只存放在群文件里的文件，需要时请把文件发到群里。
  \item \textbf{引用、@ 和按钮}：机器人可以引用某条消息回复、@群成员，也可以在消息下方附带按钮。成员点击按钮后，机器人会把这次点击当作该成员的答复继续处理。
  \item \textbf{撤回}：机器人可以在发出后 2 分钟内撤回自己的消息。
  \item \textbf{语音}：机器人收到语音消息时，会按 QQ 给出的识别文字理解内容。
  \item \textbf{群信息}：机器人可以查看群名称、简介、人数，以及自己在群里是否为管理员、能否主动发言。成员加入、退出群和入群申请会记入群聊消息记录。
  \item \textbf{需要向 QQ 申请的功能}：查看群成员列表目前只对 QQ 开放平台白名单内的机器人开放。机器人提示没有权限时，请由机器人所有者向 QQ 开放平台申请。
\end{itemize}

一个 QQ 机器人同一时间只能连接一个 Agent Swarm。更换 AppSecret 后，用同一个 AppID 再次添加即可更新凭证。

\subsection{连接 Lark}

Lark（国际版，open.larksuite.com）通过 Lark 开放平台的自建应用接入。每个应用连接一个 Agent Swarm，成员可以在 Lark 群里 @机器人，也可以和机器人私聊。Lark 应用在 Agent Swarm 的 Connections 页面用它自己的凭证连接，不使用组织 Integrations 页面里的飞书应用；同一个组织可以让一部分 Agent Swarm 连接飞书，另一部分连接 Lark。

\begin{enumerate}
  \item 在 Lark 开发者后台创建自建应用并添加机器人能力。在应用的凭证页面找到 \textbf{App ID} 和 \textbf{App Secret}，在“事件与回调”页面找到 \textbf{Verification Token} 或 \textbf{Encrypt Key}。
  \item 进入 Agent Swarm 的 \textbf{Connections}，在 \textbf{Lark} 部分点击 \textbf{Add Lark app}，填入 App ID、App Secret，以及 Verification Token 和 Encrypt Key 中的至少一个，然后点击 \textbf{Connect}。
  \item 复制页面显示的 \textbf{Request URL}。在 Lark 开发者后台的“事件与回调”中选择把事件发送到开发者服务器，保存这个请求地址，并订阅 \texttt{im.message.receive\_v1} 和 \texttt{im.message.recalled\_v1}。
  \item 在 \textbf{Lark} 部分的 \textbf{Permission scopes} 一栏点击 \textbf{Copy JSON}，复制机器人需要的全部权限。在 Lark 开发者后台打开“权限管理”，选择批量导入，粘贴这段 JSON 并保存。
  \item 创建应用版本并发布。权限和事件订阅在版本发布后才生效。
  \item 回到 \textbf{Connections}，点击该应用一行的 \textbf{Run checks}。检查会向这个应用自己的请求地址发送一次验证请求，并核对消息路由和机器人身份。需要在 Lark 开发者后台或群里手动完成的步骤会列为待处理项，结果同时记入 \textbf{Health} 页面。
  \item 把机器人加入测试群并 @它 发送一条消息，或直接私聊机器人，确认消息由预期的 Agent Swarm 处理。
\end{enumerate}

使用时请注意：

\begin{itemize}
  \item \textbf{群聊需要 @机器人}：群里没有 @机器人的消息不会交给 Agent 处理。机器人会在这条消息的话题里回复。为应用开通“获取群组中所有消息”权限并发布版本后，在机器人回复过的话题里继续发消息不用再 @它；没有这个权限时，Lark 只把 @机器人的消息发给应用，话题里的每条消息都要 @。
  \item \textbf{消息记录}：机器人收到的消息会被记录，供 Agent 搜索此前的对话。记录从应用连接之后开始；更早的群聊内容由 Agent 直接向 Lark 读取。只有为应用开通“获取群组中所有消息”权限后，群里没有 @机器人的消息才会被记录。
  \item \textbf{文件}：机器人可以发送图片（不超过 10 MB）和文件（不超过 30 MB），也可以读取成员发来的图片和文件。
  \item \textbf{云文档和妙记}：Agent 以机器人身份读取和编辑 Lark 云文档、读取妙记，规则和飞书相同：机器人只能打开分享给它所在群的文档、添加了该应用的文档，或企业内凭链接可读的文档。应用不能把文档分享给部门，只能分享给群或个人。
  \item \textbf{会议}：在群里 @机器人并附上 Google Meet 链接，或在已有会议链接的话题里请它入会；入会状态、会后纪要和文件发回同一话题。
  \item \textbf{使用 Lark 登录}：组织可以让成员用 Lark 帐号登录 Dashboard，在 \textbf{Settings} 的 \textbf{Single sign-on} 中配置，与这里连接的机器人应用使用各自的凭证。
\end{itemize}

一个 Lark 应用同一时间只能连接一个 Agent Swarm。更换 App Secret 后，用同一个 App ID 再次添加即可更新凭证。

\subsection{连接 Signal}

\begin{enumerate}
  \item 在 \textbf{Connections} 的 \textbf{Signal} 部分点击 \textbf{New code}。
  \item 在 10 分钟内，用 Signal 把页面显示的消息发送到页面给出的号码。这条消息只显示一次。
  \item 发送后，该个人或 Signal 群出现在聊天列表中。
\end{enumerate}

Signal 消息和通话音频会在 Comma 服务器上解密，以便 Agent 回复。要停止某个聊天，点击它旁边的 \textbf{Disconnect} 并确认；正在进行的通话会立即结束。

\subsection{在 Feishu 群里使用 Google Calendar 与 Google Meet}

这条能力使用 Agent Swarm 的 Google Calendar 连接和 Google Meet，不使用 Feishu 日历或飞书会议。创建日程与 Slack 使用相同方式：管理员只需先在 \textbf{Connections} 中完成 Google Calendar 授权，不需要先配置群通知。有且只有一个可用账号时，机器人直接使用该账号；有多个可用账号时，机器人会先询问使用哪一个。用户未指定日历时，Google Calendar 按该授权账号的默认日历规则处理。

到点向群里发送会议链接是独立的可选配置。需要这项能力时，管理员再为当前 Feishu connect 设置明确的共享日历、目标群和 \textbf{notify} 模式，并通过 \textbf{Run checks} 核对状态。只有配置成功且会议位于被监控日历时，机器人才会在开始时间或其后的首个扫描周期向目标群发送包含会议标题、时间和 Google Meet 链接的顶层消息；实际延迟取决于管理员配置的扫描间隔和当时的任务积压，不承诺固定的 60 秒时限（服务重启只补发开始后 5 分钟内的会议）。未配置通知不会阻止创建日程。Feishu 首版不会因为日历事件而自动入会。

\begin{enumerate}
  \item 在群里真实提及机器人并说明会议时间、时区、主题和参会人，例如“明天上午 10 点安排项目会，邀请 @Alice”。
  \item 如果参会人邮箱、时间或时区不明确，按机器人提示补充；机器人不会静默漏掉参会人。
  \item 创建成功后，核对机器人回复的日历、准确时间、参会人和 Google Meet 链接。Google Calendar 是这场会议的唯一时间来源。只有明确需要额外提醒时，才为这场会议另建 Schedule。
  \item 如果管理员配置了到点群通知，请在机器人发送的会议消息话题中真实提及机器人并说“入会”。未配置通知时，也可以在群里真实提及机器人并附上唯一的 Google Meet 链接。手工输入纯文本“@机器人名称”不算真实提及。
  \item 机器人会把等待准入、入会成功、失败和离会状态发在同一话题。话题中必须只有一个明确的 \texttt{meet.google.com} 链接；机器人最多查看该已知话题最近 50 条消息，不会扫描整个群历史。
  \item 散会后，在同一话题查看摘要、\texttt{transcript.txt} 和可用录音。每个文件独立发送，单个文件上限为 30 MB；文件缺失或超限不会阻止摘要发布，也不会重复已经成功发送的产物。
\end{enumerate}

普通定时提醒仍在任务详情中管理，并在 \textbf{Tasks} 的 \textbf{Scheduled} 视图中列出。Calendar 到点通知由管理员单独启用；没有明确需要时，不要再为同一会议配置一份重复提醒。

\subsection{连接第三方帐号}

\begin{enumerate}
  \item 在 \textbf{Connections} 的 \textbf{Accounts} 部分，从 \textbf{Connect an account} 或 \textbf{Apps via Composio} 中选择要连接的服务。
  \item 确认对话框中的说明后继续，按服务方页面提示完成授权。
  \item 返回 \textbf{Connections}，确认帐号出现在 \textbf{Connected accounts} 中，或应用显示 \textbf{Connected}。
\end{enumerate}

如果没有所需服务，请联系组织 owner 或 admin 检查 \textbf{Settings} → \textbf{Integrations} 中的 \textbf{Composio} 配置。

\section{Plugins 与 Skills}

\textbf{Plugins} 用于为当前 Agent Swarm 启用已获准的插件；\textbf{Skills} 用于查看和配置 Agent 可使用的技能。

\begin{itemize}
  \item 组织的 \textbf{Plugins}：查看组织插件和来自 Comma 的插件，点击插件查看详情。owner 和 admin 可以新建和编辑组织插件。
  \item Agent Swarm 的 \textbf{Plugins}：按名称搜索插件，按来源和状态筛选，用开关启用或停用。管理员可以点击 \textbf{New project plugin} 新建仅供当前 Agent Swarm 使用的项目插件。点击插件名称打开插件页面，查看它的 MCP 服务器和凭据；管理员可以连接、重新连接或断开凭据，确认后跳转到服务方完成授权。消息类凭据点击 \textbf{Set up in Connections}，在 \textbf{Connections} 页面设置。
  \item Agent Swarm 的 \textbf{Skills}：查看自定义技能和系统技能，点击技能名称阅读内容。管理员可以点击 \textbf{New skill} 新建技能，或点击 \textbf{Upload} 上传小于 200 KB 的 \texttt{.md} 文件（文件以 \texttt{SKILL.md} frontmatter 开头），也可以删除自定义技能。
\end{itemize}

启用前应确认插件或技能的用途和访问范围。停用前先检查依赖它的 Agent 和任务。

\section{设备}

设备为 \textbf{External Codex} Agent 提供可连接的远程工作环境。创建设备前，组织中必须有可用 Runner。

\subsection{创建设备}

\begin{enumerate}
  \item 进入 Agent Swarm，打开 \textbf{Devices}。
  \item 点击 \textbf{Add device}。
  \item 填写 \textbf{Name} 和可选的 \textbf{Alias}。
  \item 选择一个可用 \textbf{Runner}。
  \item 点击 \textbf{Create on runner}。
  \item 页面会提示设备正在连接；设备就绪后列表自动更新。再把它分配给 \textbf{External Codex} Agent。
\end{enumerate}

如果没有可选 Runner，点击 \textbf{Open Runners}。确认 Runner 在线且有足够容量后，返回设备页点击 \textbf{Check for runners}。

\subsection{维护设备}

设备不再使用时，在设备行的操作菜单中选择 \textbf{Disconnect} 或 \textbf{Delete}，确认后执行。执行前先检查仍在使用该设备的 Agent 和任务。设备状态异常时，先查看所选 Runner 是否可用，再尝试重新连接。

同一页面还包括 \textbf{Compute environments} 和 \textbf{Android setup}。

\subsection{云电脑}

页面顶部的 \textbf{Cloud VM} 区域显示此 Agent Swarm 的云电脑：它的状态（例如 \textbf{Ready}、\textbf{Sleeping}、\textbf{Waking}）、运行位置（\textbf{Cloudflare} 或组织的某台 Runner），以及此 Agent Swarm 使用的 Runner。云电脑空闲时会休眠，有任务时自动唤醒。Agent Swarm 管理员可以用该区域的开关启用或停用云电脑。

云电脑创建之前，管理员可以让它运行在组织的 Runner 上：

\begin{enumerate}
  \item 在 \textbf{Cloud VM} 区域点击 \textbf{Choose runner}。
  \item 选择一台在线 \textbf{Runner}，点击 \textbf{Use this runner}。
  \item Runner 状态显示为 \textbf{Installing}，安装完成后显示为 \textbf{Ready}。之后首次创建的云电脑会运行在这台 Runner 上。
\end{enumerate}

一个 Agent Swarm 只能使用一台 Runner。要改用另一台 Runner，先点击 \textbf{Remove runner}，再重新选择。Runner 的选择只在首次创建云电脑时生效；已有的云电脑不会移到其他 Runner 或 Cloudflare。没有选择 Runner 时，云电脑运行在 Cloudflare 上。

\section{网站}

Agent Swarm 的 \textbf{Overview} 右侧的 \textbf{Websites} 面板列出当前 Agent Swarm 下已发布的网站，最多显示 5 个，并注明其余数量。点击网站名称会在新窗口打开网站，点击发布者可以打开对应 Agent。

如果面板为空，说明当前 Agent Swarm 还没有已发布网站。

\section{Health}

\textbf{Health} 仅对 owner 和 admin 显示，用于查看组织的运行状况：整体状态及其原因、投递、集成、Runner 和设备信号的最近更新时间、最近 7 天的错误事件，以及审计记录。审计记录可以导出为 CSV。处理异常时先阅读页面提示；需要修改组织级配置时，请由 owner 或 admin 操作。

\section{常见问题}

\subsection{登录后看不到组织}

\begin{itemize}
  \item 确认登录使用的邮箱与成员记录一致。
  \item 确认选择了正确的组织。
  \item 请 owner 或 admin 在 \textbf{Members} 中检查成员状态和角色。
\end{itemize}

\subsection{看不到 Agent Swarm 或管理按钮}

\begin{itemize}
  \item 普通 member 只能看到明确授权的 Agent Swarm。
  \item 管理入口会按角色隐藏。
  \item 请 owner 或 admin 检查成员角色和 Agent Swarm 的 \textbf{Access}。
\end{itemize}

\subsection{无法创建设备}

\begin{itemize}
  \item 打开 \textbf{Fin}，确认至少一个 Runner 可用。
  \item 检查 Runner 是否仍有容量。
  \item 回到 \textbf{Devices}，重新选择 Runner 后提交。
\end{itemize}

\subsection{Feishu 检查失败}

\begin{itemize}
  \item 确认组织级 Feishu app 已启用群机器人用途。
  \item 确认当前 Agent Swarm 选择了正确的 app。
  \item 对照页面检查项核对权限、事件订阅和回调地址。
  \item 点击 \textbf{Run checks} 后，再在测试群发送消息。
\end{itemize}

如果创建 Google Calendar 日程失败，请先确认当前 Agent Swarm 已有 \textbf{ACTIVE} 的 Google Calendar 授权；存在多个授权账号时，需要明确选择一个。群通知检查未通过只表示“到点发群链接”尚未就绪，不会阻止创建日程。需要群通知时，请配置共享日历、目标群和 \textbf{notify} 模式；扫描器不会自动监控授权人的私人 \textbf{primary} 日历。会议消息未出现时，还要检查事件是否位于被监控日历、是否已取消或改期、是否包含 Google Meet 链接，以及服务重启后是否已经超过会议开始 5 分钟。

如果“@机器人 入会”没有响应，请确认使用了 Feishu 的真实提及控件，并在机器人发送会议链接的原话题中回复。散会后只有摘要没有附件时，请检查文件是否超过 30 MB、是否被删除，或机器人是否缺少群文件权限。

\subsection{Lark 没有收到回复}

\begin{itemize}
  \item 确认 Lark 开发者后台“事件与回调”中的请求地址与 \textbf{Connections} 页面显示的一致，并已订阅 \texttt{im.message.receive\_v1}。
  \item 在 \textbf{Connections} 页面点击该应用一行的 \textbf{Run checks}，先处理第一项未通过的检查。
  \item 确认应用已导入 \textbf{Copy JSON} 给出的权限，并且最新版本已经发布。
  \item 更换过 Verification Token 或 Encrypt Key 后，请用同一个 App ID 重新添加，更新连接里保存的值。
  \item 在群里需要 @机器人，并且机器人已被加入该群。
  \item 确认连接处于启用状态，目标 Agent Swarm 中有可用 Agent。
\end{itemize}

\subsection{QQ 没有收到回复}

\begin{itemize}
  \item 确认 QQ 机器人管理端的事件接收方式为 Webhook，回调地址与 \textbf{Connections} 页面显示的一致，并已订阅单聊和群聊事件。按钮点击没有反应时，请确认已订阅互动事件。
  \item 如果在 QQ 机器人管理端设置了 IP 白名单，请联系我们获取需要加入白名单的地址。
  \item 在群里需要 @机器人；未认证的机器人只能被管理员加入自己担任群主的群。
  \item 群里超过 5 分钟才有结果、却没有收到消息时，请群管理员打开“机器人主动在群聊内发言”。
  \item 确认连接处于启用状态，目标 Agent Swarm 中有可用 Agent。
\end{itemize}

\subsection{Slack 没有收到回复}

\begin{itemize}
  \item 确认应用已完成安装，并已加入测试频道。
  \item 核对页面要求的权限和事件订阅。
  \item 确认集成处于启用状态，目标 Agent Swarm 中有可用 Agent。
\end{itemize}

\subsection{任务没有继续执行}

\begin{itemize}
  \item 打开任务详情，检查是否正在等待补充信息。
  \item 确认分配的 Agent 没有被归档。
  \item 若使用 \textbf{External Codex}，确认关联设备和 Runner 可用。
\end{itemize}

\section{安全建议}

\begin{itemize}
  \item 按最小权限原则分配 owner、admin 和 member 角色。
  \item 定期检查成员、Agent Swarm 访问名单、集成和连接。
  \item 敏感凭据只填写在 Dashboard 指定字段中，不要放入任务、群聊或截图。
  \item Runner 的一次性安装命令只交给负责目标 Mac 的管理员。
  \item 成员离职、设备退役或第三方帐号不再使用时，及时撤销相应访问。
  \item 修改登录、模型或消息集成配置后，先用测试帐号和测试群验证。
\end{itemize}
